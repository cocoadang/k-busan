The same fixed-prefix JSON schema used by K-housing/K-news is emitted to existing Cloud Logging stdout. The _Default bucket was checked: 30-day retention. No public metrics API, metrics database, paid monitoring agent or extra collection schedule was introduced. Source text, prompts, report contents, identifiers, query strings, authentication headers and IP addresses are not included in these new events.

* COST_AI_CACHE_V1, scope busan_document: hit=valid persisted decision reused (relevant/irrelevant/uncertain, including held review decisions); miss=no valid stored decision; error=cache lookup failure; disabled=no cache supplied; not_eligible=no AI client. In-run relatedness/extraction use the same promise: coalesced means still running, in_run_reuse means already completed. These are not additional persistent cache lookups and must not inflate direct hit rate. Direct rate=hit/(hit+miss), with error/disabled/not_eligible/coalesced/in_run_reuse reported separately. A miss can be stopped by limits, and a cache-read error may still lead to a model request under existing behavior; neither is a billed-call count.
* COST_AI_ATTEMPT_V1: each actual OpenAI adapter request start. COST_AI_USAGE_V1: numeric input/output/cached-input/cache-write tokens and usage availability, including incomplete returned outputs when available. OpenAI output already includes reasoning. Provider cached-input/input is a separate token ratio, not app-result reuse. Do not add legacy OPENAI_USAGE logs again. Attempts with missing usage are not assumed free.
* COST_HTTP_V1: original route group captured before mounted routers, method/status, completion, conditional flag, encoded response body bytes, duration. The observer precedes compression, so it sees compression's writes to the underlying response. Tests cover real compression middleware and native-wire comparison. HEAD/304 bodies are zero. Aborted writes are separate; completed GET/HEAD is the denominator for origin 304 rate. Report per-route bytes/request, response count and statuses, excluding health/deploy probes from user-serving comparisons.

Server body-byte counters exclude protocol/TLS overhead and requests served directly by the CDN. Actual network comparison uses existing Cloud Monitoring run.googleapis.com/container/network/sent_bytes_count grouped by kind=internet/google/private, equal-length windows, request counts and deployment/source activity. A 304 has no body but still has wire headers. Pre-instrumentation AI-cache/304 rates cannot be reconstructed as if measured.
