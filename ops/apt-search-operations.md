# Apt 검색 운영 점검

검색 결과는 단지별 신고 거래가와 브랜드·역세권·대단지·신축·평지·초등학교 점수로 표시한다. 점수를 산정할 근거가 없는 항목은 미확인으로 표시한다. 같은 단지에서 여러 면적대가 검색되면 면적대별로 한 줄씩 표시한다.

## 검색 오류 확인

1. `GET /api/housing/apartment-budget` 응답 상태와 오류 발생 시각을 확인한다. 200과 빈 `results`는 후보가 없는 경우로 처리한다.
2. 503이면 같은 시간대 Apt 리비전의 Cloud Run 로그에서 `APT_BUDGET_READ_FAILED`와 조회 계약월을 찾는다. `REQUEST_FAILED`는 K-Housing API까지의 연결 실패 또는 12초 제한 초과를 뜻한다. `UPSTREAM_HTTP_ERROR`는 K-Housing이 반환한 HTTP 상태를 함께 남긴다.
3. K-Housing API가 503이면 그 리비전의 Firestore 접근과 활성 버전을 확인한다. 최근 3개 계약월에 필요한 지역별 수집본이 전부 있어야 하고, 해당 수집본 중 가장 오래된 자료를 수집한 시각이 30시간 이내여야 한다. 30시간이 지난 응답을 Apt에서 받은 경우 `SNAPSHOT_EXPIRED`를 남긴다. 저장된 거래가 있어도 수집본이 이 조건을 벗어나면 검색이 실패할 수 있다. 최종 원인은 앱 요청 시각과 운영 로그 또는 수집 시각을 맞춰 확인한다.
4. 갱신 실패가 확인되면 기존 DB를 보존한 채 별도 수집 작업을 검사하고, 다시 검색해 저장본 버전과 결과를 확인한다.

## 배포 확인

`main`에 변경이 반영되면 [GitHub Actions](../.github/workflows/deploy.yml)가 빌드와 테스트를 실행하고 Cloud Run 후보 리비전을 생성한다. 후보의 상태, 화면 번들, 검색 API, 저장된 거래 이력과 평면도를 확인한 뒤 운영 트래픽을 전환한다. 일시적인 503은 재시도하며, 후보 검증에 실패하면 현재 운영 리비전이 계속 요청을 처리한다. 전환 후 운영 주소 검증에 실패하면 직전 리비전으로 복구한다. 수동 재실행은 Actions의 `Run workflow`에서 `main`을 선택한다.

운영 화면에서는 6억~10억, 59㎡대 검색을 제출해 입지 등급표 또는 조건에 맞는 거래가 없다는 안내를 확인할 수 있다.
