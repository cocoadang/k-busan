# GPT-6 Luna 실제 문서 검증 및 Gemini 재비교

2026-11-15, 운영 배포 `c3478ec8f50148d35a810a6168011e5fb2516869`의 GPT-6 Luna 설정을 확인했다. 운영 서버와 동일한 이미지·분석 코드·키 설정으로 별도 문서 검증을 실행하고, 운영 서비스의 실제 수집·저장 경로도 `POST /api/pipeline/run?notify=false`로 확인했다. 운영 모델 설정은 변경하지 않았다.

## 운영 분석 코드 검증

조합 공개 PDF 원본 2건과 첫 PDF를 이미지로 렌더링한 OCR 입력을 사용했다. 원본은 [촉진3 조합 공고](https://dynamice.busan.go.kr/home/BARA_0000000000151/view.do?no=329&ntt_id=20680&pgMode=view)이며 파일 출처·해시는 기존 fixtures README 및 원본 결과 JSON에 보존했다. 비교 입력에 사용한 `/benchmark/` URL은 저장된 시험 파일의 식별자이며 실제 다운로드 주소는 fixtures README에 있다.

3건 모두 실제 OpenAI API 호출에 성공했고, 운영 분석기의 관련성·사건 추출·형식 검사를 통과했다. 사건 유형은 `협력업체/용역 입찰공고`, 중요도는 3, 공고일은 2026-10-08이었다. 시공사 선정 확정으로 오인하지 않았다. 평균 분석 시간은 4.20초(원문 추출 시간 제외)였다. 이 검증은 모델 호출 및 운영 분석 코드 경로 검증이며 별도 작업에서 공개 사건을 저장하지 않았다.

추가로 운영 서비스의 수집·저장 경로를 호출해 HTTP 200과 실제 `OPENAI_USAGE model=gpt-6-luna` 로그를 확인했다. 해당 주기는 13건을 시도했다. 검증 주기의 텔레그램 발송·실패는 모두 0건이며 API 응답의 일반 오류 목록은 비어 있었다. 단, 개별 분석 실패는 일반 오류 목록과 별도로 대기열에 보존되므로 이 사실만으로 모든 분석이 성공했다고 해석하면 안 된다.

점검 당시 전체 대기열은 완료 71건, 확인 필요 12건, 재시도 4건, 미처리 대기 0건이었다. 이 수치는 기존 실행도 포함하는 전체 상태이며, 아래 통제 비교의 정확도 분모가 아니다. 확인 필요에는 제목만 있거나 구체적인 사건 근거가 부족한 뉴스가 포함된다. 재시도 4건은 `AI_EVENT_INVALID` 응답 형식 검증 실패였다. 따라서 **공고 문서 분석과 API 연결은 성공했지만, 운영 뉴스 전체를 무오류로 처리했다고 볼 수는 없다.** 세부 항목은 luna-runtime-verification.json에 기록했다. 이 작업에서는 확인 대기 항목을 임의로 완료 처리하거나 검증 규칙을 완화하지 않았다.

## 통제 비교

원본 2건 + OCR 변형 1건을 모델마다 두 번씩 실행했다(각 6회). 모델 쌍마다 동일한 원문·지시·JSON 구조를 제공했고 입력 해시 일치도 검사했다. 현재 운영 조건에 맞춰 Luna는 reasoning none, Gemini 3.8 Flash는 기존 low를 사용했다. 모델의 사고 설정까지 동일하다는 뜻은 아니다. 기존 Sol 결과를 재사용하지 않고 두 모델을 모두 새로 호출했다.

| 지표 | Gemini 3.8 Flash | GPT-6 Luna |
|---|---:|---:|
| 사실 필드 일치 | 54/54 | 54/54 |
| 원문 문자열·위치 정확 일치 인용 | 30/30 | 28/30 |
| 공백을 정규화한 인용 일치 | 30/30 | 30/30 |
| 평균 API 응답 | 4.23초 | 2.58초 |
| 중앙 API 응답 | 4.25초 | 2.54초 |
| 6회 사용량 기준 비용 추정 | $0.015098 | $0.001306 |
| 같은 길이 1,000회 환산 | $2.516 | $0.218 |
| 입력 캐시 없는 1,000회 | $2.516 | $0.267~0.305 |

Luna의 인용 2건은 동일한 입찰 마감 문구에서 연속 공백을 한 칸으로 바꾼 차이다. 원문 PDF를 동일한 Poppler 방식으로 다시 읽어 공백 정규화 후 내용 일치를 확인했다. 숫자·일시가 달라진 오답은 아니며, 엄격한 문자열 일치 지표와 구분했다. 인용 일치가 모든 의미적 추론까지 보증하는 것은 아니다.

이 표본에서는 Luna가 약 39% 빠르고, 관측 사용량 기준 약 91% 저렴했다. Luna의 입력 9,102토큰 중 4,542토큰이 캐시 적중했고 Gemini는 8,726토큰 중 0토큰이 캐시 적중했다. 캐시 없는 Luna 비용 범위는 일반 입력 과금과 전량 캐시 쓰기 과금 가정의 차이다. 이번 비용 추정에는 별도 운영 코드 3회 검증·실제 수집 주기·서버·OCR 비용을 포함하지 않았다. OCR 전처리 자체는 이번 실행에서 약 14.1초였다.

가격은 청구서가 아닌 실제 반환된 토큰 사용량 × 2026-11-15 공식 Standard 단가다. [OpenAI Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)는 입력 $0.10, 캐시 입력 $0.01, 캐시 쓰기 $0.125, 출력 $0.50/100만 토큰이다. [Gemini 3.8 Flash](https://aistudio.google.com/docs/pricing#gemini-3.8-flash)는 입력 $0.75, 캐시 입력 $0.075, 출력 $3.75/100만 토큰(2026-12-31까지)이다. Gemini 단가는 2027-01-01부터 인상 예정이다.

## 판단 및 재현

이번 두 공고에서는 Luna를 계속 사용할 근거가 확인됐다. 그러나 이 결과를 전체 정비사업 뉴스의 정확도로 일반화하지 않는다. 특히 운영에서 관측된 응답 형식 오류와 원문 부족 항목은 별도 개선 과제로 남는다. 현재 모델은 Luna를 유지한다.

모든 검증에 텔레그램 발송을 사용하지 않았다. 별도 검증 작업에는 텔레그램 키 자체를 전달하지 않았고 완료 후 임시 작업을 삭제했다. 운영 키·접근 권한·예약 알림 설정은 변경하지 않았다.

원본 결과: luna-document-comparison.json, 인용 재검증: luna-quote-recheck.json, 요약: luna-comparison-summary.json, 운영 상태: luna-runtime-verification.json. 요약 재계산은 `node scripts/summarize_luna_benchmark.mjs`로 실행한다. 원본 해시·사용량·실패 항목은 JSON에서 확인할 수 있다. 타입 검사, 전체 171개 테스트(OpenAI 어댑터 검사 포함), 빌드가 통과했다.
